# DSH 工作流面板

DSH 的工作流面板：在对话区**顶部页签栏**新增一个「工作流」页签（与「对话 / 轨迹 / 上下文 / 编队」同一行），点开就是一块**只读**面板，把你的项目组织、任务、工序流水和验收结果摊在一页里看。

装好后你能看到六段：

1. **概览**——项目名、预算、数据更新时间，以及六格关键指标（任务数、完成率、过门率、人数等）。
2. **门禁六卡**——G0 到 G5 六道门，每道门显示当前结论、应产出什么、已有哪些证据；点证据文档直接在面板里看原文。
3. **里程碑**——一条横向时间线，按日期排好，缺日期的会明确标出来。
4. **组织模板**——当前编制：成员、角色、模型、任务状态、职责。
5. **任务流**——谁把活派给谁、谁又交接给谁；连线按发送方上色，鼠标停在线上能看到「哪条任务交到了哪条任务」。
6. **人员卡**——每个人的评分、模型、职责，以及**逐条任务和完成依据**（不只给分，也写明做了什么）。

面板以 Harness 原生页签呈现，排在「上下文」与「编队」之后；不占用浮动窗口，不遮挡对话，开合随 Harness 自身的页签逻辑。`Esc` 关闭证据文档的原文弹层。

## 安装

前提：DSH 桌面版（带 profile / bundles），Node.js ≥ 20。

1. 打开你的 DSH profile 目录下的 `package.json`，加两条：

```json
{
  "dependencies": {
    "dsh-workflow-panel": "github:tucaogege/dsh-workflow-panel"
  },
  "dsh": {
    "profile": {
      "bundles": [
        "<原有的 bundles 保持不动>",
        "dsh-workflow-panel"
      ]
    }
  }
}
```

2. 重启 DSH。宿主会按 `dependencies` 安装（首次需要联网拉取仓库）。

   若重启后没有自动安装，在 profile 目录执行一次 `pnpm install` 再重启。

3. 对话区顶部页签栏出现「工作流」页签即安装成功。

> 装之前建议先备份 profile 的 `package.json` 与 `cordis.patch.yml`：DSH 在异常退出后可能收窄 `bundles` 列表。

## 配置（可选）

面板默认**自动发现**项目文件：在 `$DSH_HOME/bot/workspace/*/project.json` 里取最近更新的一份。只跟踪一个项目的人通常**不需要配置**。

项目文件不在这个位置，或想固定跟踪某一项目时，在 profile 配置里显式指定：

```json
{
  "dsh-workflow-panel": {
    "projectPath": "<你的项目目录>/project.json"
  }
}
```

也可用环境变量 `DWP_PROJECT_PATH` 覆盖配置（优先级：环境变量 > 配置 > 自动发现）。

> 0.1.1 之前的版本没有自动发现，默认读插件同级的 `project.json`；若面板显示「项目文件不存在」，显式配 `projectPath` 即可。

## 只读说明

这块面板**只看不做**：

- 只发 `GET` 请求（数据快照、证据文档原文两条接口），不接受任何写操作。
- 不写任何文件，包括 `state.json` 和你的 `project.json`。
- 不派单、不审议、不修改任务状态。要派活请在 DSH 里正常对话。

面板里的结论全部来自你的 `project.json`：面板只是镜子，账没记，它就会显示「未评级 / 未提供」——这是诚实的空态，不是渲染错误。

## 卸载

1. 从 profile `package.json` 的 `dependencies` 里删掉 `dsh-workflow-panel`；
2. 从 `dsh.profile.bundles` 里删掉 `"dsh-workflow-panel"`；
3. 删掉 `node_modules` 里指向插件目录的链接；
4. 重启 DSH。

插件不写任何文件，所以删完不会有残留数据需要清理。

## 已知限制（v0.1.x）

- **派生层为空**：v1 没有派生数据源，面板固定显示「派生 0（v1 无数据源）」。
- **跨行连线是行级锚点**：交接线按成员行对齐，跨度大时线条会靠近卡片边缘而非精确指向卡片中心。
- **不写账本**：任务、评分、门禁结论都来自 `project.json`，面板不负责录入。
